# World geology data

`D-016` / `D-017`에 따라 한 층은 독립 포켓맵이 아니라 실제 월드 공간의 일부다.
따라서 자연 지형을 가진 월드/천체는 **지질 정보를 채팅이나 산문 한 줄에만 두지 않고 데이터 파일로 남긴다.**

## 파일 규칙

월드/천체가 실제 콘텐츠로 작성되면 아래 구조를 사용한다.

```text
data/worlds/<world_id>/
  geology_profile.json
```

`geology_profile.json`은 `data/worlds/geology_profile.schema.json`을 따른다.

최소한 다음을 기록한다.

- `world_id`, `terrain_body_id`, 천체 이름/종류
- 천체 전체 크기(반지름 또는 이에 준하는 기준 크기)
- 내핵/외핵/맨틀/지각 등 **깊이 또는 반지름 기준 레이어 경계**
- 레이어별 주요 재료/성분 **비율(%)**
- 지역별 지질 프로필이 필요하면 해당 지역 ID와 재료 비율
- 정확한 수치가 아직 정해지지 않은 필드는 임의 숫자를 넣지 않고 `null`/빈 배열로 남기며 `status`를 `TBD`로 표시

예를 들어 어떤 행성의 내핵/외핵 경계와 지질 비율이 두세 줄짜리 정보뿐이어도 **해당 월드의 `geology_profile.json`에 기록한다.**
게임이 전체 행성 지질을 즉시 시뮬레이션하지 않더라도 이 파일은 월드의 물리 정의 입력으로 남는다.

## 층과의 연결

각 `FloorDefinition`은 `world_region_ref`와 `geology_region_ref`(자연 지형일 때)를 통해 실제 월드 지형을 참조한다.
층마다 별도의 복제 지질을 만드는 것이 아니라 **같은 `TerrainBody`를 참조**한다.

플레이 중 굴착/붕괴/파괴로 바뀐 지형은 원본 프로필을 덮어쓰지 않는다.
변경은 `WorldState.TerrainMutationState` 계열의 **공유 동적 상태**로 저장한다. 같은 월드의 같은 좌표를 보는 다른 유배자도 동일한 변경을 본다.

## 인공 구조물

1층 사원처럼 행성의 자연 지층이 아닌 구조물도 `material/structure/durability` 인터페이스는 공유하지만,
내핵/맨틀 같은 행성 레이어를 억지로 만들지는 않는다. 이런 경우 `body_type = "artificial"` 또는 지역 구조 정의를 사용한다.

## 금지

- 지질 비율/레이어 경계를 채팅에만 남기고 저장소에는 기록하지 않기
- 같은 실제 좌표의 지형을 유배자별 `FloorState`에 복제해 서로 다른 물리 상태로 만들기
- 아직 미정인 지질 값을 구현 편의상 임의 숫자로 채우기
