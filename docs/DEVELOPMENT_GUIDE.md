# PART A — 앞으로의 개발 가이드라인

## 1. 프로젝트 한 줄 정의

「탑」은 **고정된 세계 규칙과 실제 맵·NPC·함정·아이템·전투 데이터가 존재하는 2D 도트 그래픽 반실시간 던전 크롤러**이며, AI는 게임 엔진을 대신하지 않고 NPC 대화·자유 행동 해석·동적 서술 같은 비정형 영역만 담당한다.

### 핵심 목표 (v1.1 반영)

- 플레이어는 랜덤 생성된 **유배자**로 시작해 실제 맵을 직접 이동·탐색한다. 오르골은 기본 주인공이 아니다.
- 함정·계단·아이템·NPC·투사체·전투 결과는 실제 게임 오브젝트와 데이터로 존재한다.
- 회차/월드 랜덤 결과는 생성 시 고정되며, 플레이어가 보지 않았다고 다시 생성되지 않는다.
- 전투와 이동은 턴제가 아니라 **반실시간**이다.
- 그래픽은 ASCII가 아닌 **도트(pixel art)** 기반 2D 탑다운/쿼터뷰 시점.
- **AI API가 끊겨도** 이동·전투·파밍·시간·세이브 등 핵심 게임은 동작한다.

### 프로젝트 정의 변경점 (기존 텍스트 RPG → 현재)

| 항목 | 기존 방향 | 현재 기준 |
| --- | --- | --- |
| 게임 형태 | 자유입력 중심 AI 텍스트 RPG | 실제 맵 기반 2D 던전 크롤러 |
| 기본 조작 | 텍스트 입력 | 키보드/마우스 실시간 조작 |
| AI 역할 | GM·서술 중심 | NPC 대화·비정형 행동·보조 서술 |
| 전투 | 텍스트 판정 | 실제 충돌·거리·쿨타임·투사체 기반 4단계 피해 |
| 기술 기반 | Electron/React 검토 | Godot 중심 재설계 |
| 그래픽 | 텍스트 UI | 도트 타일맵·스프라이트 |
| 주인공 | 오르골(소설 주인공) | **랜덤 생성 유배자** (오르골은 특수 개체로 분리) |

## 3. 확정 / 제안 / 미정 재정리

### 3.1 세계관에서 이미 확정된 것 (CANON, v1.1)

- 탑은 0층(공허·진입 선택) → 1층(고정 지형 특수 튜토리얼) → 2층~왕국의 문(월드별 튜토리얼 루트) → 공용 왕국 → 리프트 → 선택된 메인던전 4개(심연 고정)로 이어진다.
- 회차는 모두가 공유하는 거대 세계 단위, 월드는 그 안의 개별 세계/역사 단위. 한 회차에 복수 월드가 동시 존재한다.
- 사망은 회귀가 아니라 **새 회차 진입**(0층 복귀). 초기 스탯과 기억은 유지, 성장 스탯·스킬·칭호·아이템·현재 세계는 초기화. 유배자 총 수명 100년.
- 1층은 **고정 지형**(고대 사원풍, 천장 없는 잿빛 돌). 재생성되는 것은 전리품·유배자·상태뿐.
- 1층 서든데스는 눈을 뜬 뒤 **정확히 1시간(3600초)**. 발동 후 가장자리부터 사람 걷는 속도로 붕괴. 즉사 아님 → 계단 알면 탈출 가능.
- 1층엔 생명의 샘·마인드맵이 없고, 초기 장비는 전 유배자 공통 **대거(날 30cm+)**.
- 1층 핵심 위협은 함정과 고참 유배자. 모든 치명적 함정/억까 요소엔 **사전 단서 필수**.
- 계단은 실제로 존재하는 **파티 귀속 시설**이며 직접 발견해야 한다.
- 스탯은 **힘·민첩·지능 3종**. 초기 평균 각 10. 레벨당 스탯 포인트 1, 스탯 3점 투자 단위로 스킬 후보 발생. 하드 캡 없음.
- 특수 시설(계단/생명의 샘/모루)은 NPC에게 기본 투명+인식저해. 접촉으로 인식하면 이후 계속 보이나 이용 불가.
- 크리티컬은 랜덤 %가 아니라 실제 사건(급소·완벽 기습·특정 스킬·무기 수명 최후 일격 등)으로 발생.
- AI/GM은 이미 생성된 맵·난이도·계단·아이템·역사 결과·열매 효과를 임의로 바꾸지 않는다.

### 3.2 이번 문서에서 채택하는 구현 기준 (DESIGN)

- Godot **4.7.1 stable** + GDScript를 1차 스택으로 한다. (4.8-dev 계열 미사용)
- 32×32 타일 기본, 캐릭터 48×48/64×64 후보 프로토타입 비교. 도트 텍스처는 nearest 계열 필터 기본.
- 이동은 타일 단위 턴제가 아닌 연속 이동, 충돌/내비는 타일맵 데이터와 연동.
- 전투는 반실시간. 일반 상황 실시간, 인벤토리/전술 메뉴·마인드맵은 일시정지 또는 강한 슬로모션.
- MVP 세이브는 Godot Resource/JSON 구조화 데이터 우선, 회차/NPC 기록이 커지면 SQLite 검토.
- 성장곡선·무기 스탯 가중치 등 수치는 하드코딩 대신 Curve/데이터 파일로 관리.
- AI 호출은 일반 이동/공격에 쓰지 않고 NPC 대화·비정형 행동에만 요청.

### 3.3 여전히 미정/추후 설계 (TBD — 임의 확정 금지)

- 0층에서 100년을 전부 소모했을 때의 결과.
- 힘/민첩/지능 아래 파생 능력의 최종 목록과 계산식.
- 성장곡선 연속 보간 방식과 최종 밸런스 수치(§9 기준점은 채택).
- "2층 이후 탑 시스템 보정"의 세부 목록과 수치.
- 파티 탈퇴 시 계단 유지 vs 신규 생성 확률/조건, 파티장 변경 처리.
- 리프트 랭크 공식, 실패/탈출, 키 강제 투입 저항/보안.
- 모루 미니게임/품질/실패/강화/레시피 소비 여부, 만신전 규칙.
- 명중/회피, 부위별 급소 배율, 마법 피해/저항, 무기별 스탯 가중치.
- 심연 외 메인던전 11종 상세.
- 힘→민첩→지능→힘 상성의 실제 전투 보정 수치.
- 랜덤 유배자 생성 규칙(출신·초기 스탯 분포·특성·직업 후보).

## 4. 핵심 아키텍처

```
[INPUT]  키보드 / 마우스 / UI / 대화 입력
   ↓
[GAMEPLAY]  Player · Combat · Interaction · Inventory · Skills
   ↓
[WORLD SIMULATION]  Map · NPC · Trap · Loot · Time · SuddenDeath · Faction · CausalGraph
   ↓
[AUTHORITATIVE GAME STATE]  RunState / WorldState / FloorState · RNG 결과 · 세이브
   ↓
[AI BRIDGE]  ← 필요할 때만 호출: NPC 대화 · 비정형 행동 해석 · 보조 서술
   ↓
[VALIDATOR]  AI 제안이 규칙·현재 상태를 위반하지 않는지 검증
```

### 절대 원칙 (SSOT)

1. **게임 엔진이 진실의 단일 출처(Single Source of Truth)다.**
2. AI가 출력한 텍스트만으로 HP·아이템·위치·NPC 생존·역사 결과·계단 귀속·열매 효과를 바꾸지 않는다.
3. 모든 랜덤 생성은 시드 또는 생성 결과를 저장해 재로드 시 동일하게 복원한다.
4. 시각 오브젝트와 데이터 객체를 분리한다. 스프라이트가 화면에서 사라져도 데이터가 삭제된 것이 아니다.
5. 한 시스템이 다른 시스템의 내부 데이터를 직접 수정하지 않도록 이벤트/서비스 계층을 둔다.

## 5. 권장 기술 구성

- **게임 엔진**: Godot 4.7.1 stable (4.8-dev 미사용)
- **언어**: GDScript
- **렌더링**: 2D **TileMapLayer**/TileSet + AnimatedSprite2D 계열. (구 TileMap 노드는 deprecated → 신규 구현 금지)
- **맵**: 1층은 **고정 지형 데이터 로더** + 시드 기반 **동적 배치**(전리품/유배자/상태). 2층 이후 프로시저럴 루트는 백로그.
- **세이브**: Resource/Dictionary → JSON 또는 바이너리. 버전 필드 필수.
- **AI**: 별도 AI Bridge 모듈. 게임 루프와 완전 분리.
- **버전관리**: Git + GitHub. 의미 있는 체크포인트는 push(다른 PC에서 이어가기).

### 7.1 상태 계층

```

## 8. 반실시간 플레이 & 전투 규칙

### 8.1 이동

WASD 8방향 또는 아날로그 연속 이동. 속도는 민첩·상태이상·장비 무게·[신속] 계열로 보정. 타일은 충돌/지형/함정/소리/이동비용 정보를 주되 플레이어는 칸 단위로 끊기지 않는다.

### 8.2 시간

게임 월드 시간은 프레임이 아니라 별도 **Simulation Clock**이 관리한다. 일반 탐색 1.0×, 전술 메뉴 0×(일시정지) 또는 0.1~0.2× 슬로모션 중 설정 가능, NPC 대화는 기본 일시정지(긴 API 응답으로 서든데스 손해 방지). **마인드맵을 열면 일시정지**. 1층 시작 시 `floor_elapsed=0`, **3600초에 서든데스**.

### 8.3 전투 (4단계 피해 구조 채택 — DESIGN)

기본/강/특수 공격, 회피/대시, 상호작용, 장비·아이템 사용을 실제 입력으로 처리. 공격엔 wind-up → active → recovery 구간. 무기 리치·방향·충돌 박스·이동/투사체 속도는 실제 데이터.

```
RawAttack       = WeaponBase × StatScaling × Motion × Skill × Condition
StatScaling     ≈ √(관련 스탯의 최종 효율)
Penetration     = WeaponPenetration × StatBonus × SkillBonus × AmbushBonus
EffectiveArmor  = max(0, Armor − Penetration)
ArmorMultiplier = 100 / (100 + EffectiveArmor)
FinalDamage     = RawAttack × ArmorMultiplier ÷ BodyResilience
```

- **크리티컬은 랜덤 %가 아니다.** 급소 적중·완벽한 기습·특정 스킬·무기 수명 최후 일격 등 실제 사건이 만든다.
- 기습/암습은 피해량보다 관통·절삭 보정에 크게 작용. 무기 리치가 길수록 암습 보정 감소.
- **무기 수명**: 경험치를 주는 대상을 때리는 것이 소모 기준. 수명이 끝나는 최후 일격이 크리티컬 조건 중 하나.
- 명중/회피·급소 배율·마법 저항·무기별 스탯 가중치 수치는 **TBD**. 초기엔 복잡한 콤보보다 읽기 쉬운 전투 우선.

## 9. 도트 그래픽 가이드

- 맵 타일 32×32 기준. 플레이어/NPC는 48×48·64×64 테스트 후 하나로 고정, pivot은 타일 중심 하단 통일. 아이템 아이콘 16×16 또는 24×24, UI 아이콘 24×24 또는 32×32, 보스는 다중 타일 허용.
- 첫 애니메이션 세트: Idle 4 / Walk 6~8 / Run 6~8 / Attack 4~8 / Hit 2~3 / Death 6~10.
- 첫 단계는 화려함보다 실루엣·판독성 우선. 기본 비율 확정 후 종족/NPC 변형.
- AI 이미지 생성은 컨셉/기준안에 활용하되, 실제 스프라이트 시트는 동일 캐릭터/프레임 일관성 검수 통과 필수.
- 팔레트·외곽선 두께·광원 방향·그림자 규칙을 `assets/STYLE_GUIDE.md`에 고정.

## 10. AI 개입 범위

**AI 없이 처리**: 이동, 일반 공격, 피격, 투사체, 함정, 아이템 줍기, 인벤토리, 장비, 시간, 서든데스, 1층 지형 로드/동적 배치, 기본 적 AI, 세이브/로드.

**AI 사용**: 주요 NPC 자연어 대화, 성격/기억 기반 반응, 규칙에 없는 비정형 행동의 의도 분석(예: 밧줄+단검으로 임시 갈고리 시도), 복잡한 협상·기만·심문, 확정된 결과의 짧은 보조 서술(선택).

**AI 안전장치**: GameState 직접 mutate 금지. 구조화된 Action Proposal만 엔진이 검증 후 실행. 존재하지 않는 ID·죽은 NPC 부활·임의 아이템 생성·맵/역사/계단 변경은 거부. API 실패 시 NPC는 "응답 실패/재시도" 상태가 되고 월드 루프는 계속 정상 동작. 미래는 인과 그래프의 합법적 분기로만 바뀌며 "스토리가 재밌어 보인다"는 이유로 교체 금지.

## 13. 테스트 기준

- **1층 고정성**: 지형이 시드와 무관하게 항상 동일. (동적 배치만 시드 반영)
- **동적 배치 결정성**: 동일 시드/세이브 로드 후 전리품/유배자/함정 상태 위치 불변.
- **경로 보장**: 시드 100~1000개에서 시작점→계단 접근 불가 0건.
- **프레임 독립성**: 30/60/120 FPS에서 이동/타이머 체감 동일.
- **AI 비의존성**: API 키 없음/네트워크 오류에도 핵심 루프 플레이 가능.
- **정보 비대칭**: 미발견 함정/계단/비밀이 UI나 AI 대화로 누출 안 됨.
- **함정 단서 강제**: 치명 함정의 `clues[]`가 비어 있으면 테스트 실패.
- **세이브 마이그레이션**: 구조 변경 시 버전 상승 + 이전 세이브 처리 방식 기록.

## 14. 매 작업에서 지킬 개발 방식

작업 전 현재 PHASE와 완료 조건 확인 → 한 번에 하나의 작은 기능 묶음만 구현 → 수정하면 실제 실행/테스트 수행 → **실행 안 한 코드를 "완료"로 보고하지 않기** → 설정 원문에 없는 내용을 세계관 사실로 자동 추가 금지 → 새 제안은 DECISIONS.md의 Proposed로 → 확정 구조 변경은 CHANGELOG.md에 → MVP 범위 초과는 BACKLOG로 → 작업 종료 시 **수정 파일 / 테스트 결과 / 남은 문제 / 다음 한 단계**만 요약.

7. **상태 계층을 `RunState → WorldState → FloorState`로.** MVP는 회차 1·월드 1·1층만 채우더라도 3계층 스키마를 미리 잡아둔다.

## B3. 갱신된 "첫 메시지 명령문" (새 대화/새 작업용)

> 아래 블록을 새 작업의 첫 메시지로 복사해 쓰고, 이 문서(v2.0)를 함께 첨부한다. 이후엔 "PHASE N 계속"처럼 지시한다.

```
첨부한 「탑 — 통합 개발 가이드라인 & 즉시 적용 지침 v2.0」을 이 프로젝트의 최우선 개발 기준으로 읽고 작업을 시작해줘. 세계 설정이 충돌하면 설정서 v1.1을 우선한다.

이 프로젝트는 텍스트 RPG가 아니다. Godot 4.7.1 stable + GDScript 기반의 2D 도트 그래픽 반실시간 던전 크롤러다. 맵·함정·계단·아이템·NPC·전투 상태는 실제 게임 데이터와 오브젝트로 존재해야 하며 AI 서술만으로 처리하면 안 된다.

핵심 원칙:
1. 게임 엔진이 진실의 단일 출처다. AI는 GameState를 직접 수정할 수 없다.
2. 이동·전투·파밍·함정·시간·세이브는 AI 호출 없이 동작해야 한다.
3. AI는 NPC 대화·비정형 행동 해석·복잡한 사회적 상호작용 등 필요한 곳에만.
4. 한 번 생성된 맵·계단·함정·아이템·NPC·역사·열매 효과·랜덤 결과는 즉시 저장하고 같은 회차/월드에서 바꾸지 않는다.
5. 정식 명칭은 「탑」. 플레이어는 랜덤 유배자이고 오르골은 특수 개체다. 오르골 규칙을 일반 생성에 자동 적용하지 않는다.
6. 1층 지형은 고정이다. 랜덤은 전리품·유배자·상태뿐. 1층에 프로시저럴 지형 생성기를 만들지 않는다.
7. 스탯은 힘·민첩·지능 3종, 파생 능력은 내부 비노출값. 상태는 RunState→WorldState→FloorState 3계층.
8. 문서의 [CANON]/[DESIGN]/[TBD]/[PROPOSAL]을 구분하고, TBD 항목(파생식, 성장곡선 최종수치, 계단 리롤 확률, 리프트/모루 규칙, 명중/회피 등)은 임의 확정하지 않는다.
9. 구현은 PHASE 순서대로. 각 단계 완료 조건 통과 전 다음 단계 기능을 선행 구현하지 않는다.
10. 범위 밖 아이디어는 BACKLOG로. 실행·테스트 안 한 코드를 완료로 보고하지 않는다. 매 작업 후 수정 파일 / 테스트 결과 / 발견 문제 / 다음 한 단계만 보고한다.

먼저 PHASE 0부터 시작한다.
- 기존 프로젝트 파일이 있으면 전체 구조를 읽고 현 상태를 진단(특히 v1.0 잔재: 명칭, 1층 생성기, 6스탯 흔적).

- PHASE 0 완료 조건 충족 후 멈추고 보고한다. 지시 전 PHASE 1로 넘어가지 않는다.

이 문서를 읽은 뒤 먼저 "현재 이해한 프로젝트 정의 / PHASE 0에서 할 일 / 문서상 TBD·주의 사항"을 짧게 확인하고 곧바로 PHASE 0을 수행해줘.
