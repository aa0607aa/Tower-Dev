# docs/canon/ — Canon 색인 체계

> **이 폴더는 canon이 아니다. canon의 *색인*이다.**
> 진실의 원본은 `docs/SETTING_BIBLE_v1.1.docx`이고, 확정된 결정은 루트 `DECISIONS.md`다.
> 이 폴더와 원본이 다르면 **언제나 원본이 이긴다.** 여기를 고쳐서 canon을 바꿀 수 없다.

## 왜 만들었나

설정서는 사람이 읽으라고 쓴 산문이다. 그런데 실제 개발에서 필요한 질문은 이런 모양이다.

- "1층 서든데스가 몇 초였지? 그리고 그거 어디에 상수로 박혀 있지?"
- "계단 관련 canon 전부 보여줘. 그중 TBD는 뭐야?"
- "이 코드를 고치면 어떤 canon이 깨지지?"

산문에서는 이 질문에 답하려면 매번 전체를 다시 읽어야 한다. 에이전트가 여럿이고 서로 기억을 공유하지
않는 이 프로젝트에서는 그 비용이 그대로 사고로 이어진다. 그래서 canon을 **ID 붙은 낱개 항목**으로
쪼개고, 도메인별로 묶고, 색인 하나로 전체를 훑을 수 있게 만든다.

## 구조

```
docs/canon/
├─ README.md      # 이 문서 — 체계의 정의
├─ INDEX.md       # 전체 항목 색인 (여기부터 읽는다)
├─ WLD.md         # 세계 구조 — 탑·회차·월드·죽음·수명
├─ FLR.md         # 층 — 0층·1층·서든데스·붕괴
├─ CHR.md         # 캐릭터 — 유배자·스탯·성장·종족
├─ FAC.md         # 특수 시설 — 계단·생명의 샘·모루·만신전
├─ CBT.md         # 전투 — 반실시간·피해 구조·크리티컬·무기 수명
├─ SKL.md         # 스킬 — 마인드맵·스킬 후보
└─ SYS.md         # 메타 규칙 — SSOT·AI 개입·결정성·데이터 정책
```

예약된 도메인 (아직 파일 없음 — 내용이 생기면 만든다):

| 코드 | 범위 |
| --- | --- |
| `ITM` | 아이템·장비·열매 (현재는 FLR/CBT/WLD에 분산) |
| `NPC` | NPC·파티·팩션 |
| `HIS` | 역사·인과 그래프·신·세계 4축 |
| `DGN` | 메인던전·심연·리프트 |

## 항목 ID

형식은 `<도메인>-<번호>` — 예: `FLR-003`, `CHR-001`.

- **번호는 절대 재사용하지 않는다.** 항목이 폐기되면 번호는 `[Retired]`로 남기고 비워둔다.
  (코드 주석·커밋·다른 문서가 그 ID를 가리키고 있을 수 있다.)
- 코드 주석에서 canon 근거를 밝힐 때 이 ID를 쓴다:
  ```gdscript
  ## FLR-003: 서든데스는 눈 뜬 뒤 정확히 3600초
  const FLOOR1_SUDDEN_DEATH_SECONDS: float = 3600.0
  ```
- `DECISIONS.md`의 `D-0XX`와는 **다른 축이다.** `D-0XX`는 "언제 누가 무엇을 결정했나"(이력),
  `FLR-003`은 "지금 무엇이 참인가"(상태). 항목은 자신을 만든 결정을 출처로 가리킨다.

## 항목 형식

```markdown
### DOM-000 · 한 줄 제목

- **상태**: CANON
- **출처**: 설정서 v1.1 §0.0 · DECISIONS D-000
- **내용**: 한 항목에 한 사실만 적는다.
- **판단**: 원문이 "채택했다"고만 하고 수치를 열어뒀으므로 DESIGN으로 뒀다.
- **구현**: `data/canon/canon.gd` `SOME_CONST` · PHASE N
- **관련**: DOM-001, OTH-002
```

> 예시의 `DOM-000`은 **실재하지 않는 자리표시자**다. 예시에 진짜 ID를 쓰면 중복 검사에 걸리고,
> 무엇보다 그 ID를 검색한 사람이 예시를 실제 canon으로 오해한다. 예시에는 항상 가짜 ID를 쓴다.

필드 규칙:

| 필드 | 규칙 |
| --- | --- |
| **상태** | `CANON` / `DESIGN` / `TBD` / `PROPOSAL` 중 하나. 아래 §상태 참고 |
| **출처** | 어디서 왔는지. 출처 없는 항목은 만들지 않는다 — 그건 창작이다 |
| **내용** | 한 항목에 한 사실. 두 개면 쪼갠다 |
| **판단** | **원문을 그대로 옮긴 게 아닌 부분의 근거.** 아래 참고. 판단이 없었으면 생략 |
| **구현** | 이 canon이 닿는 코드·데이터·PHASE. 없으면 `-` |
| **관련** | 함께 봐야 할 항목 ID. 특히 **충돌 가능성이 있는 것** |

### 판단 필드를 언제 쓰나

**출처**는 "어디서 왔나"고 **판단**은 "왜 이렇게 적었나"다. 둘은 다르다.
원문을 그대로 옮긴 항목에는 판단이 없다. 하지만 아래 경우에는 **반드시 적는다.**

- **상태를 고를 때 해석이 들어간 경우** — 같은 문장을 CANON으로 볼 수도 DESIGN으로 볼 수도 있었다면
- **원문에 없는 것을 넣은 경우** — 오너 결정, 개발 가이드 유래, 합리적 추론 (예: `CHR-020`)
- **도메인 배치가 자명하지 않은 경우** — 왜 리프트가 FAC이 아니라 KGD인가
- **구현이 canon을 깰 수 있는 경우** — 순진하게 만들면 위반이 되는 지점 (예: `NPC-005`, `FAC-004`)
- **원문이 헷갈리게 쓰인 경우** — 오해를 미리 막아야 할 때 (예: `RAC-002`)

**이유**: 협업 프로토콜 §3은 "대화 내용을 인수인계 수단으로 쓰면 반드시 망가진다"고 한다.
판단을 채팅으로만 설명하고 파일에 안 남기면 **다음 세션은 결론만 보고 근거를 모른 채
그것을 뒤집거나 잘못 확장한다.** 판단 필드는 그걸 막는 장치다.

**반대로 안 쓰는 경우**: 원문을 그대로 옮긴 항목에는 쓰지 않는다.
특히 설정서 §26이 미정으로 남긴 TBD 항목들(`WLD-006` `FLR-009` `CHR-009` `CHR-010`
`CBT-006` `FAC-007` `FAC-011` `KGD-007` `DGN-003` `SKL-005`)은 **판단이 개입한 적이 없다** —
원문이 미정이라 미정으로 적었을 뿐이다. 거기에 "원문이 TBD라서 TBD"라고 쓰는 것은
잡음이고, 진짜 판단이 있는 항목을 찾기 어렵게 만든다.

## 상태

| 상태 | 의미 | 바꿀 수 있나 |
| --- | --- | --- |
| `CANON` | 확정된 세계·규칙 | 오너만. 설정서 개정이 필요 |
| `DESIGN` | 채택한 구현/밸런스안 | 테스트 결과로 튜닝 가능 |
| `TBD` | 의도적 미정 | **임의 확정 금지.** 채우려면 오너 결정 필요 |
| `PROPOSAL` | 미승인 제안 | 오너 승인 전엔 canon이 아니다 |

**`TBD` 항목도 반드시 등재한다.** "아직 안 정했다"는 것 자체가 중요한 정보다. 등재해 두지 않으면
다음 세션의 에이전트가 빈칸을 발견하고 "합리적인 기본값"을 지어낸다. 그게 이 프로젝트에서 가장
자주 일어날 사고다.

## 규칙

1. **여기서 canon을 만들지 않는다.** 원본이나 DECISIONS에 없는 내용을 항목으로 추가하지 않는다.
   필요하면 `[CANON CONFLICT]` 양식(COLLABORATION_PROTOCOL.md §2)으로 오너에게 올린다.
2. **원본과 어긋나면 이 폴더를 고친다.** 원본을 고치지 않는다.
3. **한 항목에 한 사실.** "1층은 고정 지형이고 서든데스는 3600초다"는 두 항목이다.
4. **TBD를 조용히 채우지 않는다.** 구현하다 막히면 멈추고 물어본다.
5. 항목을 고치면 `INDEX.md`도 같이 고친다. 색인과 본문이 어긋나면 색인을 신뢰할 수 없게 된다.

## 왜 JSON 색인을 두지 않았나

에이전트가 정확히 뽑아 쓰기엔 JSON이 나아 보이지만, 마크다운 본문과 JSON 색인을 **둘 다 유지하면
반드시 어긋난다.** 어긋난 순간 둘 중 뭐가 맞는지 아무도 모르게 되고, 이 체계의 존재 이유가 사라진다.
그래서 단일 소스로 간다. `INDEX.md`의 표는 고정 열 순서를 지키므로 grep으로 충분히 기계 처리된다.

```
grep -rn "TBD" docs/canon/          # 미정 항목 전부
grep -rn "FAC-" docs/canon/         # 계단·시설 관련 전부
grep -rn "FLR-003" . --include=*.gd # 이 canon을 참조하는 코드
```
