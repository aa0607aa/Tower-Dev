### 3차 — 판단 근거 감사 (2026-08-17)

오너 지적: "내용을 추가할 때 근거도 함께 적고 있나?"
확인 결과 **출처는 141/141 적혀 있었지만 판단 근거는 20/141뿐이었다.**
협업 프로토콜 §3("대화를 인수인계 수단으로 쓰면 망가진다")을 색인 자체가 어기고 있었다.

조치:

- 항목 형식에 **판단** 필드를 추가하고 언제 쓰고 언제 안 쓰는지 규정 (README §판단 필드)
- 해석이 들어간 **DESIGN·혼합 상태 항목 전부**에 판단을 backfill
- 원문 §26이 미정으로 남긴 순수 TBD 10건은 **면제** — 판단이 개입한 적이 없다
- 이 감사가 **중복 2건**을 드러내 정리했다:

  | 중복 | 조치 |
  | --- | --- |
  | `WLD-008` ↔ `ITM-002` (열매 효과) | WLD-008을 포인터로 축소. ITM-002가 원문 절과 일치 |
  | `WLD-009` ↔ `HIS-002`+`HIS-004` (4축·인과) | WLD-009를 포인터로 축소. WLD 쪽은 2차 출처였고 한 항목에 두 사실이 섞여 있었다 |

  둘 다 2차에서 `HIS`·`ITM` 도메인을 신설하며 재등재하고 **원본 항목을 지우지 않아** 생겼다.
  도메인을 새로 만들 때는 기존 항목을 반드시 정리한다.

재감사 명령:

```
# ID 중복 검사
Get-ChildItem docs\canon\*.md | Where-Object { $_.Name -notin 'README.md','INDEX.md' } |
  Select-String '^### ([A-Z]{3}-\d{3})' | ForEach-Object { $_.Matches[0].Groups[1].Value } |
  Group-Object | Where-Object Count -gt 1

# DESIGN·TBD인데 판단 근거가 없는 항목 (§26 순수 TBD 10건은 면제)
# 전체 스크립트는 CHANGELOG의 3차 감사 항목 참고
```

**중복 검사는 기계로 되지만 내용 중복은 안 된다.** 도메인을 신설하거나 항목을 옮길 때
사람이 직접 확인해야 한다. 위 2건이 그 증거다.
