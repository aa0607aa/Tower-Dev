## 3. 반드시 지킬 Canon / Hard Rule

### 3.1 함정 — `FLR-011`, `FLR-012`, `FLR-028`

- 치명 함정은 **발동 전에 알아챌 수 있는 유효 단서**가 있어야 한다.
- 벽 화살/볼트 같은 발사형 함정은 한 번 발동하면 재충전되지 않는다.
- 함정은 `PlayerBody entered` 전용 장치가 아니다.
- **actor class가 아니라 trigger mechanism을 모델링한다.**
- 돌·투척물·다른 물체·환경 변화가 실제 메커니즘상 감지부/작동부를 건드릴 수 있으면
  플레이어 몸이 아니어도 발동·소모·우회할 수 있어야 한다.
- 반대로 모든 함정이 모든 물체에 반응한다고 일반화하지 않는다. 생체/마법/특정 조건 감지 등은
  각 함정 데이터가 정한 메커니즘을 따른다.

현재 `floor1_layout.json`에는 `wall_bolt / pitfall / snare` 타입과 `lethal / one_shot / clues`가 있지만
**정확한 trigger mechanism 필드는 아직 없다.** PHASE 3에서 이 경계를 데이터로 만든다.
원작/Canon에 없는 구체 센서 구조를 세계관 사실로 만들지 말고, 현재 게임 구현에 필요한 메커니즘 표현은 DESIGN으로 기록한다.

### 3.2 아이템 — `ITM-001`, `FLR-014`

- 물건은 기본적으로 실제로 들고 다닌다. 아공간 인벤토리를 기본값으로 만들지 않는다.
- 1층 스폰 무기는 대체로 품질은 나쁘지만 초기 대거보다 실전 가치가 높다.
- 운반 무게/힘 보정의 **정확한 수치식은 PHASE 6/TBD**다. PHASE 3에서 임의 용량 수치를 Canon처럼 만들지 않는다.

### 3.3 상태 소유권 — `WLD-003`, `FLR-024`, `SYS-003`

- `FloorState`는 층의 동적 결과다.
- 지형 mutation과 같은 공유 월드 물리 상태는 `WorldState` 소유다.
- **플레이어가 들고 층을 넘어갈 인벤토리를 `FloorState`에 영구 소유시키지 않는다.**
- 현재 저장소에 완전한 `RunState/WorldState` 컨테이너가 아직 없다면, Claude는 PHASE 3에서 필요한 최소 소유권 구조를
  먼저 제안/구현하되 `RunState → WorldState → FloorState` 3계층 Canon을 깨지 않는다.
- 시드는 재생성용 진실이 아니다. 실체화된 아이템/함정 결과를 저장하고 재로드 시 그대로 복원한다.

### 3.4 정보 비대칭 — `SYS-005`

- 미발견 함정·계단·비밀을 일반 UI에 자동 노출하지 않는다.
- 현재 F1 `DebugOverlay`는 개발 도구일 뿐 배포 게임 정보 계층이 아니다.
- 실제 함정/아이템 표현이 붙으면 `DebugOverlay` 의존을 제거하고, 삭제 또는 개발 전용 경로로 격리한다.

### 3.5 행동 반경

- 유배자가 던진 물체/투사체도 `CausalSource`상 유배자 인과다.
- PHASE 3에서 던지기/물체 상호작용을 추가할 경우 `AccessEnvelope.can_cross()` / `AccessService.can_effect_reach()` 경계를 우회하지 않는다.
- NPC/야생동물의 독립 행동은 같은 경계에 막히지 않는다.

## 4. 권장 티켓 분해

### P3-T0 · PHASE 전환/계약 정리

- `CURRENT_STATE.md`를 PHASE 2 `PLAYTESTED` 완료 / PHASE 3 착수로 갱신.
- `CHANGELOG.md`에 `P2-REV-004~007`, `D-025/D-026`, PHASE 2 종료를 동기화.
- `TEST_CHECKLIST`에 오너 layout 재플레이 완료를 기록.
- GPT 보조 로그가 있으면 `docs/log/2026-08.md`에 병합 후 보조 파일 삭제.
- 전체 테스트를 한 번 더 실행해 기준선을 고정.

### P3-T1 · 상호작용 입력과 대상 선택

목표: 아이템/함정/계단 등 앞으로 붙을 상호작용이 각자 입력을 훔치지 않게 공통 경로를 만든다.

- `interact` 입력 액션 추가.
- 근거리 상호작용 후보 조회 + 결정적 우선순위/선택.
- 상호작용 가능 여부와 표시 문자열을 **발견된 정보 범위** 안에서만 제공.
- 함정의 존재/종류를 미발견 상태에서 상호작용 프롬프트가 누출하지 않게 테스트.

완료 조건: 같은 공간에 후보가 여러 개 있어도 선택이 결정적이고, 미발견 비밀을 UI가 새지 않는다.

### P3-T2 · ItemInstance + 인벤토리 소유권

목표: `loot point의 추첨 결과`와 `플레이어가 실제로 들고 있는 물건`을 분리한다.

- 안정적인 `item_instance_id`를 가진 최소 ItemInstance 데이터.
- FloorState의 loot는 **바닥/층에 존재하는 물건 상태**를 표현.
- 플레이어가 들고 있는 inventory는 유배자/회차 수명주기에 귀속.
- 무게 제한 공식, 장비 스탯, 전투 성능은 아직 만들지 않는다.
- 같은 세이브 재로드에서 instance ID/소유자/위치가 그대로 복원.

**주의:** 현재 `FloorState.loot[point_id]`의 `looted=true`만으로 인벤토리를 표현하면
`버리기`, `다시 줍기`, `층 이동`에서 소유권이 꼬인다. 이 단계에서 분리한다.

### P3-T3 · 바닥 아이템 실체 + 줍기/버리기

- FloorState 결과를 실제 월드 오브젝트/뷰로 표시.
- 줍기: floor/world ownership → exile inventory ownership.
- 버리기: exile inventory → 현재 월드 위치의 floor/world ownership.
- 버린 아이템은 원래 loot point로 순간이동하지 않는다. **실제 버린 위치**를 저장한다.
- 동일 아이템 복제/소실 방지용 불변식 테스트.

완료 조건: `줍기 → 저장 → 로드 → 버리기 → 저장 → 로드 → 다시 줍기`가 같은 instance를 유지.

### P3-T4 · 함정 trigger mechanism 계약

먼저 구조만 만든다.

예시 인터페이스 개념:

```text
TrapDefinition
- trap_id
- trap_type
- trigger_mechanism / accepted stimulus
- lethal
- one_shot
- clues[]

TrapStimulus
- source / CausalSource
- physical kind
- world anchor / trajectory / weight·impact 등 필요한 최소 사실

TrapRuntime
- can_trigger(def, stimulus)
- trigger(def, state, stimulus)
```

필드명은 구현 담당이 조정 가능하다. 핵심은 `body is Player` 같은 actor-class 조건을 정본으로 삼지 않는 것이다.

현재 1층 `wall_bolt / pitfall / snare`의 정확한 센서 방식이 원문에 없는 부분은 **DESIGN**으로 구분한다.
어떤 구체 메커니즘을 채택할지 Canon처럼 서술하지 않는다.

### P3-T5 · 실제 함정 동작 + 저장

- 최소 1종 발사형(`wall_bolt`)을 실제 runtime 경로에 연결.
- 정상 메커니즘을 만족하는 **비플레이어 물리 자극**으로도 발동 가능한 E2E를 반드시 둔다 (`FLR-028`).
- 발동 시 `FloorState.fire_trap()`가 실제 경로에서 호출되고 `fired=true`, `armed=false`가 저장된다.
- 재로드 후 재충전되지 않는다.
- pitfall/snare도 같은 mechanism layer를 사용하되, 모든 타입을 동일 센서로 뭉개지 않는다.

### P3-T6 · 단서 표현 / 정보 비대칭

- `clues[]`가 단순 텍스트 데이터로만 존재하지 않고 화면/환경에서 관찰할 수 있게 최소 greybox 표현을 붙인다.
- 단서는 위험을 100% 정답 표시하는 UI 아이콘이 아니라 **위험을 추론할 근거**여야 한다.
- 어떤 단서가 발견됐는지 상태가 필요하다면 저장한다.
- F1 DebugOverlay 없이도 오너가 치명 함정의 사전 단서를 알아챌 수 있는지 확인한다.

`PHASE 8`에서 최종 픽셀아트가 들어오면 도트 가독성은 다시 확인한다. PHASE 3에서는 기능적/greybox 인지 가능성을 먼저 검증한다.

### P3-T7 · PHASE 3 종합 회귀 + 오너 PLAYTEST

자동:
- `3-1` 치명 함정 단서 강제.
- `3-2` 줍기/버리기/재로드 동일 instance/ownership.
- `3-3` 발사형 함정 1회성 + 저장.
- 비플레이어 물리 자극이 메커니즘상 합법하면 함정 발동.
- 미발견 함정 정보 UI 누출 없음.
- 유배자 인과 물체가 AccessEnvelope 경계를 넘지 않음.
- AI 없이 전부 동작.

오너:
- `3-4` F1 디버그 마커 없이 실제 플레이하며 치명 함정 전에 단서를 인지/의심할 수 있는지 확인.
- 상호작용 키와 줍기/버리기 감각 확인.
