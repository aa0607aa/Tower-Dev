## 1. 이번 대화에서 오너가 직접 확정/재확인한 것

### 1.1 1층 함정 — 위치와 종류는 고정

- 1층의 **함정 위치와 함정 종류/구조는 고정**이다.
- 회차/월드에서 바뀌는 것은 함정의 **활성 여부, 이미 소모되었는지**, 주변의 루팅/전투 흔적 같은
  동적 상태다.
- 따라서 `D-016` 초안의 "slot은 고정, trap type은 시드 랜덤" 해석은 폐기한다.
- `SYS-014`의 "함정 종류는 숨길 수 있다" 문구는 설정서 §6.1보다 랜덤 범위를 넓힌 잘못된 요약이므로
  정식 반영 때 정정해야 한다.
- 고정 함정에 종속된 고정 단서는 고정 정의에 둘 수 있고, 이미 작동한 흔적 같은 동적 단서는 상태에 둔다.

### 1.2 계단 — 층 진입 시 결정

- 계단 위치 결정 시점은 **층 진입 시**다.
- 그 시점에는 해당 층의 스토리라인/주요 사건/공간 정보가 이미 준비되어 있어야 한다.
- 파티에 합류하면 파티장의 기존 계단 이용권으로 귀속하는 현재 `FAC-005` 규칙을 유지한다.
- 탈퇴 시 기존 계단 유지/신규 계단 판정의 정확한 확률은 기존 `FAC-007` TBD를 유지한다.

### 1.3 계단은 생성 뒤 좌표 고정 + 파괴 불가

- 계단은 한 번 생성되면 **해당 월드 공간 좌표에 고정**된다.
- 계단을 지지하던 지형이 이후 파괴/붕괴되어도 계단 좌표 자체는 이동하지 않는다.
- 계단은 **파괴 불가능한 특수 시설**이다.
- 따라서 계단 좌표는 단순 `walkable floor cell`보다 넓은 공간 주소를 표현할 수 있어야 한다.

### 1.4 파밍 tier hint 없음

- 고정 파밍 지점에 `tier_hint`를 두지 않는다.
- 탑은 특정 위치가 좋은 보상을 준다고 친절하게 알려주는 구조가 아니다.
- 로그라이크의 랜덤성을 유지한다.

### 1.5 생성 결과 저장

- 동적 배치 결과는 **실제 생성 결과를 저장**한다.
- seed도 재현/디버깅용으로 함께 보존한다.
- 고정 정의가 패치된 경우를 구분하기 위해 definition version/hash를 함께 저장하는 방향에 동의한다.

### 1.6 층은 독립 포켓맵이 아니라 실제 월드의 일부

오너가 재설명한 기존 설정의 의도:

- 실제 대륙/행성의 지리 데이터는 플레이어가 보고 있는 층 영역 밖에도 **계속 존재**한다.
- 한 층은 그 실제 세계의 특정 위치 중 **유배자에게 허용된 일정 부분**이다.
- 유배자는 허용 영역 끝에서 보이지 않는 "맵의 끝"에 막혀 더 나아갈 수 없다.
- 경계 밖에도 실제 환경·생태·NPC가 존재한다.
- 일반 NPC와 야생동물은 유배자의 "맵의 끝" 제약을 받지 않고 경계를 자유롭게 넘나들 수 있다.
- 같은 실제 위치라도 유배자별 허용 영역은 서로 **겹칠 수도, 겹치지 않을 수도 있다.**
- 일반적인 층보다 허용 영역이 크게 잡힌 형태를 **와이드 맵**이라 부른다.
- 일반적인 맵 크기는 해당 층의 메인 스토리 중요도/복잡도와 비례하는 경향이 있다.

현재 v1.1에는 "보이지 않는 행동 반경"(`§7.2`, `FLR-017`)까지만 남아 있고,
위의 **실제 세계 지속성 / NPC의 경계 통과 / 유배자별 중첩 / 와이드 맵** 상세는 빠져 있다.
정식 Canon 색인에 복원할 필요가 있다.

### 1.7 튜토리얼 홀수층 / 짝수층

오너가 재설명한 기존 설정의 의도:

- **홀수층**: 유배자별 **개별 목표**를 가진 층. 공간이 겹치고 서로 만날 수 있더라도 목표는 각자다.
  즉 "솔로층"은 인스턴스에 혼자 갇힌다는 뜻이 아니다.
- **짝수층**: 여러 유배자가 **공통 목표**를 가지는 층. 협동, PvP, 경쟁, 정해진 인원만 생존하는
  미션 등이 가능하다.
- 짝수층은 여러 유배자가 같은 허용 영역("맵의 끝")을 공유하는 경우가 많다.
- 현재 v1.1 전문에는 이 홀수/짝수 규칙이 남아 있지 않다. 정식 Canon 색인에 복원할 필요가 있다.

### 1.8 지형은 현실의 물질처럼 파괴 가능

- 지형을 전부 "절대 파괴 불가 벽"으로 취급하지 않는다.
- 자연 지형은 실제 행성처럼 지질/지층의 구조를 가지며, 지형 물질에는 현실성을 가진 내구/저항이 있다.
- 플레이어는 충분한 힘·도구·시간을 쓰면 지형을 실제로 파괴하고 세계를 변경할 수 있다.
- 힘 10의 일반 성인이 부적절한 도구(예: 숟가락)로 큰 토량을 파는 것은 현실적으로 매우 오래 걸려야 한다.
- 전체 지형 값을 처음부터 전부 메모리에 펼칠 필요는 없다. 세계적으로 존재하는 구조를 정의해 두고,
  실제 상호작용이 필요한 위치의 값만 나중에 결정적으로 materialize하는 방식은 허용한다.

## 2. GPT 보완 — 계단 배치의 목표를 "최악의 한 점"이 아니라 "공정한 악의"로 정의

오너의 의도는 "플레이어 입장에서 제일 빡치는 위치"다. 이 의도는 유지하되 **단일 최대값 argmax**로
구현하지 않는 것을 권고한다.

단일 공식으로 항상 가장 높은 점수를 고르면 플레이어가 공식을 알아낸 뒤 역산하기 쉽고,
매번 극단적인 장소만 선택되어 패턴이 단조로워질 수 있다.

권장 목표:

> **스토리적으로 의미가 있고, 층을 쉽게 스킵하지 못하게 하며, 충분히 멀고 위험/탐색 비용이 있지만,
> 정상적인 플레이로 반드시 도달 가능한 후보군 중 하나를 선택한다.**

### 2.1 Hard Constraint — 하나라도 실패하면 후보 탈락

1. **스토리 정합성** — 현재 활성 스토리/인과 분기에서 존재할 수 있는 위치여야 한다.
2. **최종 도달 가능성** — 해당 층의 정상적인 수단으로 결국 접근할 수 있어야 한다. 영구 소프트락 금지.
3. **안티 스킵** — 시작 직후 시야/짧은 직선 이동만으로 우연히 통과 가능한 위치는 제외한다.
4. **행동 반경 정합성** — 최종적으로 플레이어에게 허용되는 영역 안이거나,
   정상 스토리 진행으로 해금되는 허용 영역 안이어야 한다.
5. **시간 예산** — 지형 파괴가 필수라면 필요한 도구/힘/시간이 해당 층의 서든데스와 모순되면 안 된다.
6. **공간 주소 유효성** — 일반 바닥뿐 아니라 지하 공동/상부 공동/구조물 아래 등도 가능하지만,
   월드 공간 모델 안에서 실제 존재하는 위치여야 한다.

### 2.2 Soft Score — "빡침"을 여러 축으로 분해

- `story_relevance`: 메인 사건/보스/핵심 장소와의 연관성
- `skip_resistance`: 층 목표를 건너뛰고 바로 계단으로 갈 수 없는 정도
- `normalized_route_cost`: 고정 미터가 아니라 **해당 유배자 허용 영역의 크기/유효 경로 길이에 대한 비율**
- `risk_exposure`: 위험 지역·보스·적대 세력 등과의 연관
- `discovery_friction`: 숨은 통로, 시야 차폐, 정보 수집 필요성
- `terrain_access_cost`: 굴착/파괴/우회 등 물리적 접근 비용
- `novelty`: 최근 회차와 같은 유형의 위치가 반복되는 것을 억제

거리 항목은 단순 유클리드 거리보다 **실제 이동 가능한 경로 비용(geodesic/path cost)의 percentile**을
우선한다. 큰 맵에서는 500m, 작은 맵에서는 500m가 전혀 다른 의미이기 때문이다.

### 2.3 최종 선택 — 상위 후보군에서 시드 기반 가중 랜덤

- 모든 후보 중 점수 1등을 항상 고르지 않는다.
- Hard Constraint를 통과한 후보에서 상위 밴드(예: 상위 일정 percentile)를 만들고,
  그 안에서 seed 기반 가중 랜덤으로 하나를 선택한다.
- 정확한 percentile/가중치는 DESIGN 수치이며 플레이테스트로 조정한다.

이렇게 하면 "탑이 악의적으로 골랐다"는 느낌은 유지하면서도 **항상 수학적 최댓값**이라는 역산 지문을 줄인다.

## 3. GPT 보완 — AI는 계단을 직접 생성하지 않고 Proposal/Ranker 역할

현재 `SYS-001/002/007`을 유지하려면 외부 AI/LLM이 GameState에 좌표를 직접 써서는 안 된다.
또 AI API가 실패해도 게임은 진행되어야 한다.

권장 파이프라인:

```text
층 진입
  ↓
엔진: 현재 스토리 + 허용 영역 + 지형/위험/POI로 합법 후보 생성
  ↓
엔진: Hard Constraint 필터
  ↓
AI(선택): 후보의 스토리 의미/악의적 적합성을 구조화 Proposal로 rank
  ↓
Validator: 존재하지 않는 좌표·소프트락·스토리 위반 제거
  ↓
엔진: 상위 밴드에서 seed 기반 선택
  ↓
party_stairs[]에 실체화 + 결과 저장
```

AI가 없거나 실패하면 **엔진의 정량 scorer만으로 같은 절차를 완료하는 fallback**을 둔다.
AI는 스토리의 의미를 읽는 보조 평가자이지 게임 진행의 필수 의존성이 아니다.

### 성능

계단은 매 프레임 계산하는 것이 아니라 **층 진입 시 한 번** 계산하므로 실시간 성능 문제는 작다.
문제는 전 행성의 모든 좌표를 후보로 훑는 것이다. 그렇게 하지 않는다.

- 현재 유배자의 허용 영역 + 정상 진행으로 열릴 인접 영역만 대상으로 한다.
- POI, 보스 구역, 막다른 길, 숨은 공간, 지하/상부 공동, 고위험 구역 등으로 **희소 후보 집합**을 만든다.
- 일반 지형에서는 공간 샘플링/경로 그래프를 사용하고 모든 셀을 LLM에 넘기지 않는다.

## 4. GPT 보완 — 지형/층 데이터 구조는 `map_bounds`보다 큰 모델이 필요

이번 오너 설명을 따르면 `FloorState.map_bounds: Rect2i` 하나는 잘못된 추상화가 된다.
경계는 **월드 자체의 끝이 아니라 유배자에게 부여된 접근 권한의 끝**이기 때문이다.

권장 책임 분리:

```text
WorldState
  └─ WorldTerrainDefinition / TerrainBody
       ├─ 실제 대륙·행성·구조물의 연속 공간
       ├─ 지질/재료/구조 정보 (필요 시 lazy materialize)
       └─ TerrainMutationState (파괴·굴착·붕괴 등 저장)

FloorDefinition
  ├─ world_region_ref           # 이번 층이 가리키는 실제 장소
  ├─ story/objective graph
  ├─ authored overlays / POI
  └─ floor rules

FloorState
  ├─ loot / NPC / trap state
  ├─ party_stairs[]
  ├─ sudden_death / event state
  └─ access_by_exile_or_party[] # 유배자별 허용 영역
```

`Rect2i`는 broad-phase/AABB 최적화용으로 쓸 수 있지만 **Canon의 "맵의 끝" 정본은 아니다.**
허용 영역은 polygon/cell mask/region graph 등 비정형 표현을 사용할 수 있어야 한다.

### 계단 좌표

단순 `Vector2i cell` 대신 장기적으로 다음 정도의 **WorldAnchor**가 필요하다.

```text
WorldAnchor {
  world_id,
  region_id,
  x,
  y,
  layer_or_depth
}
```

2D 화면을 유지해도 논리 공간에는 `layer_or_depth`를 둘 수 있다. 그러면 동굴 천장 위 공동,
지하 공간, 건물 하부처럼 같은 XY에서 다른 높이/깊이를 구분할 수 있다.

## 5. GPT 보완 — "행성 전체 데이터"는 완전 저장이 아니라 완전 주소 가능 + lazy resolution

오너가 원하는 "빠지는 부분 없이 실제 세계가 존재"를 모든 타일/복셀을 처음부터 저장하는 것으로
구현하면 메모리/세이브 크기가 불필요하게 폭발한다.

권장 의미:

> **세계의 모든 좌표는 어떤 지형/물질이 존재하는지 결정할 수 있는 규칙을 가진다.**
> 아직 플레이어나 시뮬레이션이 필요로 하지 않은 좌표는 값을 materialize하지 않아도
> "존재하지 않는 것"이 아니다.

예:

```text
Planet/TerrainBody profile
  → core / mantle / crust / regional geology
  → region seed + authored historical overrides
  → 필요해진 chunk/layer만 deterministic resolve
  → 파괴/변경된 부분만 mutation delta 저장
```

**1층처럼 인공 구조물/공허 위 시설에는 행성 내핵을 억지로 적용하지 않는다.**
공통 인터페이스를 `TerrainBody`로 두고 자연 행성은 지질 레이어를, 인공/마법 구조물은
별도의 재료/구조 레이어를 사용하도록 하는 것을 GPT가 권고한다.

## 6. GPT 보완 — 현실적인 지형 내구도

정확한 현실 물성치를 전부 시뮬레이션할 필요는 없지만 **현실에서 납득되는 작업량**은 유지한다.

권장 모델:

```text
필요 굴착/파괴 작업량
≈ 재료 저항(material resistance)
 × 제거 부피(volume)
 × 구조/압축 보정

플레이어 작업률
≈ STR 기반 작업 능력
 × 도구 효율(tool efficiency)
 × 숙련/스킬/상태 보정
```

- 흙, 점토, 풍화암, 화강암, 철근/석조 등은 다른 저항을 가진다.
- 힘이 높아도 **숟가락의 형상/재료 한계** 때문에 암석을 효율적으로 부술 수 없다.
- 좋은 곡괭이/폭발물/마법은 효율을 크게 바꿀 수 있다.
- 정확한 수치·공학식은 DESIGN/TBD로 두고 플레이테스트에서 시간 스케일을 맞춘다.
- 향후 천장/지지 구조 파괴가 중요해지면 전체 유한요소 해석 대신 **로컬 support/collapse 규칙**을 사용한다.

PHASE 2에서 완전한 굴착 시스템까지 만들 필요는 없다. 다만 데이터 모델이 나중에 지형 내구도와
mutation을 넣을 수 없게 굳어지는 것은 피해야 한다.

## 7. 현재 남은 오너 확인 / 추후 설계 질문

### O-1 · 겹치는 행동 반경은 같은 WorldState를 공유하는가

GPT 권고: **공유한다.** 같은 실제 대륙/장소라는 설정을 유지하려면, 두 유배자의 허용 영역이 겹친 곳에서
한쪽이 벽을 부수거나 NPC를 죽였을 때 다른 쪽도 그 결과를 보는 것이 자연스럽다.
그렇지 않으면 같은 좌표에 복제된 평행 지형이 생긴다.

### O-2 · "맵의 끝"은 플레이어 본체만 막는가

오너 설명은 NPC/야생동물이 자유롭게 통과한다고 확정했다. 아직 불명확한 것:

- 플레이어가 발사한 투사체
- 소환물/펫
- 던진 아이템
- 플레이어가 미는 물체

이들이 경계를 넘을 수 있는지는 나중에 악용 가능성이 크므로 별도 규칙이 필요하다.

### O-3 · 계단 AI 평가 구조

오너가 원하는 "스토리 연관 + 스킵 방지 + 맵 비율 기반 거리"는 위 §2~§3 구조로 구현 가능하다.
GPT는 **AI 직접 결정이 아니라 엔진 후보 생성/검증 + AI 선택적 rank + seed 상위밴드 선택**을 권고한다.
이 구조를 D-016의 계단 배치 설계로 확정할지 오너 확인이 필요하다.

### O-4 · PHASE 2의 지형 저작 SSOT

기존 `TileMapLayer + FloorDefinition`보다 이번 세계 구조는 더 큰 추상화를 요구한다.
GPT 권고:

- 1층 회색박스 저작은 여전히 TileMapLayer 사용 가능.
- TileMapLayer는 **편집/표시 입력**이지 전체 세계의 SSOT가 아니다.
- 실제 공통 구조는 `WorldTerrainDefinition/TerrainBody + FloorDefinition + FloorState`.
- 완전한 행성/지질 생성과 굴착 시뮬레이션은 PHASE 2 범위를 넘기되, 인터페이스와 mutation hook은 지금 확보한다.

## 8. 다음 AI에게

- `D-016`은 아직 구현 착수 전 설계 단계다.
- 오너가 확정한 Q0(함정 고정), Q3(층 진입), Q4(no tier_hint), Q5(결과 저장)는 되돌리지 않는다.
- 기존 `SYS-014`의 "함정 종류 시드" 문구는 정정 대상이다.
- 기존 `map_bounds`를 월드 경계로 해석하지 않는다. 새 설정상 **유배자별 접근 경계**다.

- 계단 AI는 `SYS-002/007`을 깨지 않도록 Proposal + Validator + deterministic fallback 구조로 검토한다.
- 지형 파괴는 1층의 "초기 지형 고정"과 충돌하지 않는다. **고정은 초기 정의**, 파괴는 이후 동적 mutation으로 분리한다.
