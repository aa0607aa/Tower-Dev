### B-001 · 데이터 마이닝 대응 Tier 3 — 실제 볼륨·더미 콘텐츠

- **출처**: DECISIONS `D-012` Q2 (오너: "나중에 하자")
- **내용**: 배포 데이터에 실제 볼륨을 확보하고 더미를 섞는 층.
- **왜 지금 안 하나**: 진짜 콘텐츠가 아직 없다. 그리고 `SYS-009` Tier 2 때문에
  **더미는 진짜와 같은 불변식을 전부 만족해야 하므로 진짜만큼 비싸다.**
  MVP 전에 쓸 예산이 아니다.
- **다시 볼 시점**: 콘텐츠 제작 단계 (PHASE 8 이후)
- **주의**: 그때 유일하게 유효한 형태는 **"실제로 낮은 확률로 등장하는 진짜 콘텐츠"**다.
  등장하지 않는 가짜를 넣으면 코드 참조 대조 한 번에 걸러진다.
  **지금 데이터 포맷에 예비 필드를 넣지 않는다** (오너 결정).
- **관련**: `SYS-009`, `docs/DATAMINING_POLICY.md` §8

### B-002 · 2층 이후 프로시저럴 초기 지형 생성기

- **출처**: DECISIONS `D-003` · canon `FLR-003`
- **내용**: 1층은 고정 **초기 지형**이므로 1층 생성기를 만들지 않는다. 이 기술은 폐기가 아니라 이동이다.
- **주의**: `FLR-027`의 플레이 중 지형 파괴/굴착은 프로시저럴 **초기 지형 생성**과 별개다.
- **다시 볼 시점**: 2층 이후 구현 (MVP 이후)
- **관련**: `FLR-001`, `FLR-003`, `FLR-027`, `D-017`

### B-003 · 배포 빌드의 렌더링 경로 결정

- **출처**: PHASE 0 환경 이슈 (2026-08-17)
- **내용**: 현재 개발 PC는 네이티브 OpenGL 종료 시 크래시해 `--rendering-driver opengl3_angle`로
  우회 중이다. 이는 **로컬 실행 옵션일 뿐 `project.godot`에 넣지 않았다.**
  배포 시 Windows에서 ANGLE을 기본으로 쓸지, 네이티브 GL을 쓰고 실패 시 폴백할지는 별도 결정이다.
- **왜 지금 안 하나**: 개발 PC 한 대의 낡은 드라이버로 전체 플레이어의 렌더링 경로를 정할 수 없다.
- **다시 볼 시점**: PHASE 11 (안정화·빌드)
- **관련**: `docs/TEST_CHECKLIST.md` 환경 이슈 절

### B-004 · 자동 테스트 러너 도입 — **Resolved**

- **상태**: **완료 / 백로그 종료** (2026-08-18)
- **출처**: DECISIONS `D-015`
- **결정**: PHASE 1부터 **자체 `SceneTree` 테스트 러너**를 사용한다. GUT은 현재 도입하지 않는다.
- **원칙**: 테스트 본문은 순수 함수 + 작은 assertion helper 중심으로 프레임워크 중립성을 유지한다.
  runner/helper 유지비가 커지거나 fixture/mock/비동기/리포팅 요구가 반복되면 GUT 등 외부 프레임워크를 재검토한다.
- **현재 상태**: PHASE 1에서 구현 완료. Player E2E/충돌 통합 테스트까지 보강됨.
- **관련**: `tests/README.md`, `docs/TEST_CHECKLIST.md`, `D-015`

### B-007 · 전체 행성 지질·굴착·붕괴 시뮬레이션

- **출처**: `D-017` · `FLR-027` · 2026-08-18 오너 지형 물질성 확정
- **내용**: 자연 세계가 내핵/맨틀/지각/지역 지질로 이어지는 구조, 재료별 저항, 굴착/파괴 작업량,
  지지 구조와 붕괴, 지형 mutation의 장기 시뮬레이션을 완성하는 작업.
- **왜 PHASE 2에서 전부 안 하나**: PHASE 2의 핵심은 1층 초기 지형/상태 포맷이다. 여기서 완전한
  행성 복셀·지질·구조 해석까지 구현하면 범위가 폭발한다.
- **PHASE 2에서 반드시 확보할 것**:
  - 실제 월드 위치를 참조할 수 있는 공간 주소
  - terrain/material profile을 나중에 연결할 인터페이스
  - 지형 파괴/변경을 저장할 mutation hook
  - 고정 초기 정의와 동적 mutation의 분리
- **후속 구현 방향**: 모든 좌표를 미리 저장하지 않고 **결정적으로 주소 가능 + 필요 시 lazy materialize +
  변경된 부분만 delta 저장**. 정확한 물성 수치는 플레이테스트/밸런스와 함께 정한다.
- **다시 볼 시점**: 2층+ 월드 지형 생성 또는 굴착이 실제 핵심 플레이로 들어가는 단계
- **관련**: `FLR-023`, `FLR-027`, `SYS-003`, `docs/design/PHASE2_WORLD_SPACE_EXTENSION.md`
