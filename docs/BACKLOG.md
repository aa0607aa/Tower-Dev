# BACKLOG — 나중에 할 것

> 개발 가이드 §11 운영 원칙: **새 기능 아이디어는 바로 넣지 말고 여기에 기록한다.**
> MVP 범위를 넘는 것(§12)도 여기로 온다.
>
> 여기 있는 항목은 **하기로 정해진 것이 아니라 잊지 않기로 정해진 것**이다.
> 착수하려면 오너 결정이 필요하다.

### B-001 · 데이터 마이닝 대응 Tier 3 — 실제 볼륨·더미 콘텐츠

- **출처**: DECISIONS `D-012` Q2 (오너: "나중에 하자")
- **내용**: 배포 데이터에 실제 볼륨을 확보하고 더미를 섞는 층.
- **왜 지금 안 하나**: 진짜 콘텐츠가 아직 없다. 그리고 `SYS-009` Tier 2 때문에
  **더미는 진짜와 같은 불변식을 전부 만족해야 하므로 진짜만큼 비싸다.**
  MVP 전에 쓸 예산이 아니다.
- **다시 볼 시점**: 콘텐츠 제작 단계 (PHASE 8 이후)
- **주의**: 그때 유일하게 유효한 형태는 **"실제로 낮은 확률로 등장하는 진짜 콘텐츠"**다.
  등장하지 않는 가짜를 넣으면 코드 참조 대조 한 번에 걸러진다.
  **지금 데이터 포맷에 예비 필드를 넣지 않는다** (오너 결정).
- **관련**: `SYS-009`, `docs/DATAMINING_POLICY.md` §8

### B-003 · 배포 빌드의 렌더링 경로 결정

- **출처**: PHASE 0 환경 이슈 (2026-08-17)
- **내용**: 현재 개발 PC는 네이티브 OpenGL 종료 시 크래시해 `--rendering-driver opengl3_angle`로
  우회 중이다. 이는 **로컬 실행 옵션일 뿐 `project.godot`에 넣지 않았다.**
  배포 시 Windows에서 ANGLE을 기본으로 쓸지, 네이티브 GL을 쓰고 실패 시 폴백할지는 별도 결정이다.
- **왜 지금 안 하나**: 개발 PC 한 대의 낡은 드라이버로 전체 플레이어의 렌더링 경로를 정할 수 없다.
- **다시 볼 시점**: PHASE 11 (안정화·빌드)
- **관련**: `docs/TEST_CHECKLIST.md` 환경 이슈 절

### B-004 · 자동 테스트 러너 도입 — **Resolved**

- **상태**: **완료 / 백로그 종료** (2026-08-18)

- **다음 작업**: PHASE 1 착수 시 `tests/runner.gd` 골격과 첫 이동 테스트를 구현한다.
- **관련**: `tests/README.md`, `docs/TEST_CHECKLIST.md`, `D-015`
